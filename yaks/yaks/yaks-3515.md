Follow-up to [yaks-bdf9](/yaks/yaks/yaks-bdf9.md) (decided 2026-10-31: store commit hashes in yaks). That decision was **built for the CLI**:

- `yaks land` writes `kind: landed` notes (`commit`, `source`, `branch`);
- workers write `kind: checkpoint` notes;
- `yaks commits <id>` reads those first.

This farm has 126 landed and 20 checkpoint notes across 96 yaks. Since then the TUI has gained a code viewer, the directory view, the take-out menu, host links and a history. This yak redesigns the **affordance**: how a commit reads, links, opens and shows, in the TUI and on GitHub.

## Where it stands

- **A commit is inert text everywhere.** A landed note's header shows the full 40-character hash as plain text, cut off at the pane edge. It isn't a link and can't be opened. The 365 backticked short hashes in yak prose are plain text too.
- **No link form for a commit itself.** `code:path@sha` names a file *at* a commit; nothing names the commit. yaks-390f (host URLs read back as code links) is the same resolver problem.
- **No view of a commit:** its message, the files it touched, the diff.
- **"Where is this yak's code" lives only in the CLI** (`yaks commits`). The yak detail pane doesn't show it.
- **On GitHub, a hash in a farm file never links.** GitHub autolinks hashes in issues, not in repository markdown.

## Proposed shape (leans; questions in the ask)

- **Data:** notes stay the truth (append-only, attributed, merge-safe). Any per-yak summary is derived on read, never a stored field ("any index is derived").
- **Grammar:** a `Link::Commit { sha }` that the resolver also gets from the code repo's host commit URL (`https://github.com/o/r/commit/<sha>`), sharing yaks-390f's URL-to-code-link reader. Hashes are stored full and shown short.
- **TUI:**
  - a note's `commit:` and `source:` values become short-hash links;
  - Enter opens a **commit view** in the pane: subject and body, author and date, then the changed files with `+/-` counts;
  - Enter on a file opens the code viewer at that commit (already supported);
  - `O` takes it out (`g` host commit URL, `p` copy hash);
  - `o`/`i` history works as for any pane document;
  - a worker hash that was squashed says "landed as `<landed>`", from the `source:` mapping;
  - a commit missing here says so, and offers `yaks commits --fetch` and the host link.
- **Yak detail:** a derived `Code:` row (landed commits, checkpoint branches), opening that list, as the `Attachments:` row does.
- **Writers:**
  - `yaks land` writes the body line as a host link, so it also works on GitHub;
  - `yaks update --commit [<rev>]` (default `HEAD`) records a `commit:` with the full hash, checking that it exists (and, with yaks-ab81, that it is pushed).
- **Phases:** grammar and resolver, then the TUI links and commit view, then the `Code:` row, then the writers. An inline diff view comes last.
