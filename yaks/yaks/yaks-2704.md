Prototype for yaks-9bcd's storage decision (Joel, 2026-11-27: "tantivy only if it solves the whole problem without an external dep; otherwise SQLite with FTS5; measure a cold-cache build").

Build two throwaway prototypes **outside the yaks repo** (a scratch cargo project), each indexing a farm's markdown files:

- **SQLite FTS5** via `rusqlite` with the `bundled` feature: an FTS5 table over (path, kind, title, tags, body) with `unicode61 remove_diacritics 2` and prefix indexes; plain tables for link edges (source path, target, anchor) and per-file modified times from one `git log --name-only` pass.
- **tantivy**: a schema with the same text fields (positions on), and whatever tantivy offers for the edges and times; record what needs a second store.

For each, on this farm (copy it: `cp -r $(yaks path) <scratch>`) and on a synthetic farm of 10k yak files (generate realistic ones: frontmatter, 1-3 KB body, a few links):

- cold-cache full build time (drop caches as far as macOS allows: `sudo purge` is not allowed; instead build on a freshly copied directory and report it as "fresh copy"), warm rebuild, incremental update of one file;
- index size on disk; release binary size added to a hello-world;
- query latency: a word, a prefix (as-you-type), a quoted phrase, a field scope (`tag:tui`), a backlink lookup;
- whether an identifier-aware pre-tokenizer (`issues/123` → `issues`, `123`, `issues/123`; `yaks-ca59` → `yaks`, `ca59`, `yaks-ca59`) is easy to plug in;
- does it build for the five release targets (`.github/workflows/release.yml`; check documentation, not by cross-compiling all five).

Deliverable: a report attached to this yak, a `Decision:`-style recommendation note (not the decision itself: the yakherd and Joel decide), and the prototype source attached as a directory.
