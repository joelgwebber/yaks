Part of yaks-0229 (scope agreed by Joel). The TUI can't look through a set of files: a directory source's `files/`, a yak's attachment directory `<herd>/yaks/<id>/`, or a dok's sibling directory. System-open on a `.tgz` attachment unpacked it into the farm.

## Want

1. **A directory view in the right pane** (a new `DocView` kind beside `Text` and `Image`). It shows the directory's entries as a tree (dirs first, sorted). `j`/`k` move. `Enter` opens a file in the existing text or image viewer, through the same path a followed link takes, so the history (`o`/`i`) works, and expands or collapses a directory. `O` takes the selected file out (the existing take-out menu). `Esc` comes back.
2. **Reached by:**
   - following a farm link that names a directory (`<id>/somedir/`, `/sources/<id>/files/`);
   - a row in a yak's detail pane when its attachment directory has files ("attachments (n)"), and the same for a dok in the Doks viewer;
   - a source's view.
3. **Archives are never system-opened from the TUI.** `.tgz .tar .tar.gz .zip .7z .gz .bz2 .xz` on `Enter` or system-open say `<name>: an archive; O → p copies its path`. The take-out menu's path and editor entries still work.

New keys go in `src/tui/keymap.rs` `BINDINGS` under the repo's key rules (AGENTS.md "Key bindings"). Update `docs/tui.md`, the `?` help, and the docshots if a scene fits.

## Evidence

Headless frames of the browser on a nested attachment directory and on a directory source's `files/`, attached. A test that `Enter` on an archive does not call the OS opener. `cargo test -p yaks`.

Design read (browse-1), after reading `tui.rs`, `follow.rs`, `handlers.rs`, `history.rs`, `keymap.rs`, `takeout.rs`:

- `DocView::Dir(DirView)` in a new `src/tui/dirview.rs`; a new key context `Ctx::Dir`. No new `Cmd`: the view reuses `move.*`, `pane.enter`, `tree.toggle|left|right`, `pane.close`, `take.out`, `nav.back|forward`, `row.copy`, so every command already has keys in both families.
- A directory link needs the grammar to allow it: `links::parse` refuses a trailing `/` today (`clean` returns None, the link becomes `Upward`). I trim trailing slashes on a farm path and let the TUI decide by `is_dir` on disk, so `<id>/dir/`, `/sources/<id>/files/` and the slash-less forms all resolve the same.
- Rows into the view: a yak's detail pane gets an `Attachments:` field row (a link) when `<herd>/yaks/<id>/` holds files; the Doks viewer gets the same row for a dok (sibling dir) and a source (`files/`).
- History: `PaneAt::Doc` gains the folded-dir set, so `o` after opening a file from the view lands on the same tree.
- Archive guard lives in `App::os_open`, the single funnel to the OS opener (Enter on an attachment link, take-out `o`); the dir view's Enter never reaches it.

Milestone 1 (browse-1): the view works end to end in the headless TUI on a scratch farm (`target/release/yaks`, farm `r-76c7979b`, throwaway).

Observed, not assumed:

- A yak with `proj/src/deep/...` plus `bundle.tgz`: the detail pane gets `Attachments: 8 files`; Tab + Enter opens the tree; `Enter` unfolds `proj/`, `src/`, `deep/`; `Enter` on `notes.md` opens the text viewer; `o` returns to the tree with the same folds open.

- A dok with a sibling directory shows `Attachments: 2 files`; a source shows `Files: 5 files`; both open the view. Links in a dok body (`design-notes/`, `/sources/<bare id>/files/`, `/yak/yaks/yak-0a96/proj/src/`) all open the directory view, and the peek pane lists the directory's top level.
- Dot files (`.config/`, `.gitignore`) are listed, per srccli-1's change that directory sources and attached dirs keep them; only `.git` and symlinks are hidden.
