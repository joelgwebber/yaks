Now that we have links working really well across yaks, doks, commits, attachments, and so forth, and all reflected as links within the GHUI and others like it -- I think it's time to revisit whether it makes sense to allow links across farms.

In previous discussions, we had shied away from this problem, because it was really tricky to handle on local checkouts, without knowing where they are (and because they can differ across machines). But we *can* make them work sanely across hosted repos, because the URL is all we need. Eg, if I want to link to a dok in another farm, I could just use a URL [like this](https://github.com/joelgwebber/yaks/blob/yaks/doks/design/farm-layout-and-links.md), and it would mostly work, at least in the hosted UI. But we could also add some affordances to simplify creating and following these links within the TUI. It's worth a research & design pass to think through how best to approach this.

Note: I don't think this means we should support cross-farm links like parent/child relationships, dependencies, and so forth. Those are all part of an appropriately special-cased class that I think should remain farm-local. Trying to make that work across farms would, I think, be far too brittle.
