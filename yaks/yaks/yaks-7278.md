Decision 5 of [the changelog design](/doks/design/changelog.md#5-changelogmd-is-a-projection-per-branch). Keep a Changelog file for the checked-out branch: releases whose tags HEAD reaches, latest first, plus Unreleased. Farm links to web URLs via src/hosting.rs when the farm branch is published, plain text otherwise; pinned images as github.com/<o>/<r>/raw/<sha>/<path> (serves LFS; raw.githubusercontent.com does not). One release's text is the GitHub Release body. Committed with the version bump (RELEASING.md).

#### 2026-11-21T23:52:20Z

*clog-1*

Decision: releases = `git tag --merged HEAD --list <glob> --sort=-v:refname` with `-c versionsort.suffix=-` (newest version first; v1.0.0-rc1 before v1.0.0). Rejected: `--sort=-creatordate` (a late tag or a backport tag on an older version would reorder history) and topology (git has no sort for it; version order is what readers expect and what the file is titled by).
Decision: Unreleased: if a release dok exists for a version that is not tagged and its range: ends at HEAD (or empty), that version leads as `## [v0.0.41] - Unreleased` (newest such dok); otherwise `## [Unreleased]` when latest-tag..HEAD has non-merge commits, omitted when none. Rejected: always `## [Unreleased]` plus a separate section (would list the same changes twice), and `## [v0.0.41] - unreleased` lowercase (Keep a Changelog writes `Unreleased`).
Decision: `--release` names a section by its version (or `Unreleased`), case-insensitive; an unknown one errors listing what exists. Rejected: silently printing nothing.
Decision: links go through `Space::web_url` per distinct link (cached), unpinned for yaks/doks; images ask with pin=true, then derive raw from the URL web_url gave by `Repo::parse_url` + new `Repo::raw_url` (GitHub raw/<sha>, GitLab -/raw/<sha>, Gitea raw/commit/<sha>). A farm link with no URL becomes its text (image: its alt text); stderr gets ONE "note:" naming the count and first reason, plus one more for links that lead nowhere until pushed. Rejected: one note per link (a release has hundreds); building URLs by hand.
Decision: dok headings are demoted by one level with a floor of `###` (a stray `# x` in a body becomes `###`, never colliding with the release's `##`), ignoring fenced code; link rewriting uses pulldown-cmark offsets like links::rewrite, so code spans are untouched. Rejected: regexing the text.
Decision: a release with no dok is generated through the same `entries` fn `block` now calls (block split in two, output unchanged: release_dok tests pass); open/dead/no-change yaks are not listed, matching the dok.
Decision: generation cost: ~1.5 s per tag with no dok (git log + farm load per tag), so the first run over this repo's 40 tags took 66 s (single `--release` takes 2-4 s). Not optimized (out of scope; the backfill writes doks and removes it); documented in docs/cli.md.
