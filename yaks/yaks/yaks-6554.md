The TUI renders `<!-- ... -->` as literal text (inline HTML is not rendered). Release doks (yaks-c708) wrap their generated block in `<!-- yaks:changes -->` / `<!-- /yaks:changes -->`, so the markers show in the pane; GitHub hides them. A whole-line or block HTML comment should render as nothing. Evidence: yaks-c708/release-dok-frame.txt. Update the yaks skill's 'Notes and descriptions' line (inline HTML shows as literal text) and src/brief.rs notes line if the rule changes.

#### 2026-11-22T17:05:12Z

*html-1*

Decision: an HTML block is buffered until its end and laid out by one function (`hide_comments` in `src/tui/mdrender.rs`), not hidden event by event. Rejected: dropping `Event::Html` that starts with `<!--` (a multi-line comment arrives as several events, and a block of only comments would still open a block and owe a blank row).

#### 2026-11-22T17:05:13Z

*html-1*

Decision: the rule lives in `mdrender::render_in`, the only markdown-to-rows path. `detail::md_rows` (detail pane, dok viewer, attachment viewer) all call it, and `markdown_lint`/`links` only parse events, never show text, so there was no per-caller copy to change. Rejected: stripping comments from the source before parsing (it would put a comment in a code fence at risk and shift the line numbers rows map back to).

#### 2026-11-22T17:05:14Z

*html-1*

Decision: in an HTML block, a line holding only a comment is dropped, but a line with a comment plus other HTML keeps the rest (`<div><!-- c -->hi</div>` shows `<div>hi</div>`); an unterminated `<!--` hides to the end of the block, as CommonMark's block ends there. Inline, a comment is skipped and a space it leaves beside another collapses (`text <!-- n --> more` shows `text more`), as HTML does. Rejected: leaving the double space.
