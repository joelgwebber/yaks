Decision on [yaks-49c5](/yaks/yaks/yaks-49c5.md) (Joel, 2026-11-14): source directories carry a readable slug, `sources/<date>-<sha8>-<slug>/`, slug from the title, "as long as we can implement the de-duping stuff reliably". This yak is that implementation; the rename of existing sources is part of the schema-9 migration ([yaks-acc0](/yaks/yaks/yaks-acc0.md)), which uses what ships here.

## Scope

- **Id vs name:** the source's identity stays `<date>-<sha8>`; the slug is a suffix of the directory name only. Everything that resolves a source by id (`source list`, `source mark`, `--part-of`, `sources:` citations, `/sources/<id>`, `locate::farm_file`, `doctor`, `check`) must find it by that prefix, so a citation or link written without the slug (all of today's) keeps resolving until `yaks migrate` rewrites it.
- **Dedup:** `source add` of bytes already saved returns the existing source whatever `--title` says, and never renames or creates a second one. Match on the `<date>-<sha8>` prefix only. A test per case: same bytes and same title, same bytes and a different title, same bytes saved on another day (today's rule: check what `sha8` and the date mean in `sources.rs` and keep it), and two different files whose sha8 collide.
- **Refresh:** `--refresh` keeps the id; if the title changes, the slug in the directory name is NOT changed (record that as a `Decision:`: a rename would break every link), and `yaks source mark` / `list` show the current title from `source.md`.
- **Slug rule:** lowercase, the GitHub-style slug of the title (reuse `links::slug`), at most 48 characters cut on a word, `untitled` when empty, ASCII only (transliteration is not needed: drop what is not alphanumeric). A path-safe check: no `/`, no leading dot.
- **New writes:** `source add` and `yaks promote` write the new name from the start. Reading accepts both names, always.
- **Migration hook:** a pure `sources::plan_slugs(root) -> Vec<(old, new)>` (idempotent: a directory that already has a slug yields nothing) for the migration yak to apply with `git mv`, plus a function that rewrites a link or a `sources:` entry from the old id form to the new path. Do not wire either into `yaks migrate`.

## Out of scope

`migrate.rs`, `store::SCHEMA`, link rewriting in doks and yaks, the resolver (`locate.rs` only to make `farm_file` find a directory by its id prefix, which is its job already).

## Evidence

Unit tests for each dedup case above and for resolving an unslugged id when only the slugged directory exists; a run of `yaks source add` twice with different titles on a scratch farm showing one source; `yaks source list` and `yaks peek /sources/<old-id>` on a scratch farm where the directory carries a slug; `plan_slugs` over a COPY of this farm's `sources/` directory (214 entries) printed in a note, including any slug collisions it finds (two titles giving the same slug get a `-2` suffix: say how you handled it). Docs: `docs/cli.md`, the clap help for `source add`, the `yaks-research` skill's "Save before you rely on it" section.

Decision: slug collision between two different sources (same title, different bytes) needs no `-2` suffix at all. Their ids (`<date>-<sha8>`) differ, so `sources/<id>-<slug>` never clashes; the suffix is never put on the id. Rejected: a `-2` counter on the slug (it would be dead code, and would hide the one real collision, an id collision, behind a rename). The only clash is two different contents with the same `<date>-<sha8>`: `add` now refuses it with an error instead of overwriting the old directory (today's code silently overwrites), and the message says to save it another day. Test: `two_different_files_whose_sha8_collide_are_refused_not_overwritten`. `plan_slugs` cannot produce a clash either; two directories that share an id (an unslugged one beside a slugged one, e.g. from two branches) are left out of the plan and reported by `duplicate_ids` for a person.

Decision: `--refresh` never renames. A retitled source keeps `sources/<id>-<old-slug>/` (a rename would break every link); `source.md` has the current title and `list`/`mark` read it from there. Test: `refresh_keeps_the_directory_when_the_title_changes`.

Decision: `locate::farm_file` stays lexical (the TUI, which I may not edit, calls it); new `locate::farm_file_in(root, path)` does the id-prefix lookup and `links::exists` and `links::peek` call it. The TUI's `read_farm_doc`/`read_doc` still use the lexical one, so opening a bare-id source link in the TUI will not find a slugged directory until `tui/follow.rs` switches to `farm_file_in` (two one-line call sites at follow.rs:96 and :209): a follow-up for whoever owns tui/*.

Decision: `check.rs` (`uncited`) takes the id from the directory name (`id_of` closure) and compares it with ids found in citations. For a slugged directory the dir id is `<id>-<slug>` while today's citations say `<id>`, so a slugged source would be reported uncited. check.rs is not mine (check-1); the fix is `sources::id_of(name)` there (and for a citation, the same). Flagging it to the coordinator before the migration lands.

Decision: `plan_slugs` takes the slug from the `title:` field of `source.md` itself, not `Source::title`, which falls back to the file name `source` when the field is missing.
