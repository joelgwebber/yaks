From cowpaths/joel's feedback dok (2026-11-10 entry, [the session](/sessions/2026/11/claude-2026-11-10-1653-personal-agent-protocol-sources-browser.md) is in that farm): commits were stamped `delta:PAP` after `yaks whoami --set` in an earlier call; `YAKS_ACTOR` on every command was the fix.

## Cause (reproduced on 0.0.38)

`actor::set_config` writes `yaks.actor` to the config of the git checkout the command runs in: `--worktree` config for a linked worktree, `--local` for a clone. The farm's own worktree (`yaks path`) is a linked worktree, so a name set there is invisible from the code checkout, and vice versa for the code checkout's worktree config. Delta clones are separate repositories, so each one starts unnamed.

- Set in the code checkout: read from the farm dir and via `-C`: works.
- Set from inside the farm worktree (`cd $(yaks path) && yaks whoami --set x`): read from the code checkout: `delta:PAP (from harness environment)`.
- In cowpaths/joel today: the farm worktree has `yaks.actor=delta-agent`; the checkout has none.

`whoami --set` prints which file it wrote ("this worktree's git config"), but not that other checkouts of the farm will not see it.

## Options

- Resolve `yaks.actor` from the farm's worktree config as well as the cwd's (the farm is the one place every checkout shares), keyed by thread so two threads don't share a name.
- Or key the name by `harness_thread()` in a per-user cache (yaks-5d1c chose git config to survive fresh shells; a thread-keyed entry survives them too and follows the thread across clones).
- At least: `whoami --set` run inside the farm worktree says that the code checkout will not see it.

Related: yaks-5d1c (introduced `whoami --set`), yaks-35b5 (one farm worktree per repository), yaks-d11e (`touched` missed this actor's writes).
