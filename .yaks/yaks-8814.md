Seen 2026-10-12 on the real machine: land-1's shed (worker clone for yaks-ed5e) reads `farm: 1 moved, 17 new notes, 1 needs, 1 edited` instead of `landed`, although everything it did is in main. The one thing keeping it outstanding is its copy of yaks-ed5e still carrying `needs: human` (its blocked ask), which main later resolved (answered, picked up, needs cleared, then shorn). `outstanding_ids` treats any `needs:` the shed has and the reference lacks as outstanding, even when the reference has moved past it.
Refine: a shed's `needs:` is superseded (not outstanding) when the reference has no `needs:` on that yak AND the reference's notes include the shed's ask entry plus a later answer/pickup (or the reference yak is shorn). Same direction-aware spirit as the status_rank fix in yaks-ed5e. Evidence: a fixture with exactly this case reads `landed`; a shed whose ask the reference never saw stays outstanding.
