The primary's row is measured from `origin_base` (`refs/remotes/origin/main`, else `origin/HEAD`) whatever branch it is on. On a feature branch (surveyor: `kinds-discovery`, 90 commits ahead of origin/main, even with origin/kinds-discovery) that lists the whole branch arc as unpublished, though nothing is.

Decided (Joel, 2026-10-16): measure the primary against its branch's upstream (`@{u}`), else `origin/main` as now, else its fork point. The `(vs ...)` marker names the ref actually used (e.g. `(vs origin/kinds-discovery)`). Branches that do not line up across remotes are not a case to design for.

Questions to settle in the work and record as Decisions:
- `reference_tasks` (what `landed` is measured against) falls back to `origin_base` when the primary is not visible. It should probably follow the same rule (the primary's upstream).
- JSON `farm.vs` today is `origin`; keep that value with a new field naming the ref, or a new value. Either changes the documented contract, so update docs/cli.md, README.md, `.agents/skills/yaks/SKILL.md` and the `Sheds`/`Changes` help in src/main.rs.
- A branch with an upstream that was never pushed (`@{u}` set but the remote ref missing) falls back to origin/main.

Evidence: a test where the primary is on a branch tracking `origin/<branch>`: its row is measured from that ref and the marker says so; a primary on `main` is unchanged. Real machine: from surveyor, `main` reads `(vs origin/kinds-discovery)` and shows only unpushed farm changes.

Decision: one rule, `upstream_base`, for the primary's baseline and for `landed`'s reference when the primary isn't visible (Joel: keep the rules coherent). The order is the branch's `@{upstream}`, then `origin/<branch>` (a branch pushed without `-u`), then `origin/main` / `origin/HEAD` (detached HEAD, or a branch never pushed), then the fork point. JSON: `farm.vs` `origin` is renamed `upstream`, and the ref goes in a new `farm.upstream` (also on `yaks changes --json`). Clearest for readers; Joel confirmed there are no programmatic consumers. The text marker names the ref, e.g. `(vs origin/kinds-discovery)`.
