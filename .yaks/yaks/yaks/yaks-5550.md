**Decision (yakherd):** make it a command, `yaks import-hearth <repo> [--dry-run]`, not a one-off script. The Hearth data repo needs the same import once Hearth sits on a yak herd (yaks-44b3), so it recurs.

**What `joel` holds** (`~/src/fs/joel`, main 3bf78fe): `wiki/` (31 pages), `raw/sources/` (37 sources, 8.8 MiB), `schemas/agent-platform.md`, `raw/sessions/YYYY/MM/*.review.md` (7 session reviews), `schedules/` (Hearth jobs), plus `notes/` and `projects/`, which stay on `main` as code. Pages link sources as `../../raw/sources/<id>/x.png`, cite them as `raw/sources/<id>/source.md` under `sources:`, and link each other relatively (`../projects/sightmap-ios.md`).

**Task.** Import a Hearth-layout repo's knowledge into the farm, copying, never deleting from the source repo:

- `wiki/**` → farm `wiki/**`, same paths.
- `raw/sources/<id>/` → farm `sources/<id>/`, byte for byte (ids and `source.md` are already Hearth's format, which yaks reads).
- `schemas/*.md` → farm `schemas/`.
- `raw/sessions/**` → farm `sessions/**`. Write a `Decision:` note if you place them differently, because a top-level dir must not look like a herd to doctor.
- Rewrite links in imported pages, and in `source.md`'s `part_of`/`superseded_by`:
  - `raw/sources/` → `sources/`;
  - relative `../` links → farm-root `/wiki/...` and `/sources/...` (yaks forbids `../`; see the `links` module);
  - `sources:` entries `raw/sources/<id>/source.md` → `sources/<id>/source.md`.
  - Rewrite by byte range with `links::rewrite`, so nothing else changes.
- Links that point outside what is imported (into `notes/` or `projects/`) become `code:` links (`code:notes/x.md`). Report them.
- Refuse to overwrite an existing different file in the farm. Re-running is idempotent: identical files are skipped.
- One commit per import on the farm branch (the per-change commit machinery, or `commit::run`), with a message naming the source repo and its HEAD.
- Print a report of what moved, links rewritten, links left pointing outside, and doctor's findings after. `--dry-run` writes nothing.
- `schedules/`, `core/`, `instructions/`, `views/` and `.agents/` are NOT imported (they are Hearth's harness side). List them as skipped.

**Scope.**

- New `src/hearth_import.rs`.
- A `ImportHearth` subcommand variant plus its dispatch arm in `src/main.rs`. Put it next to `Merge`; only that region, since another worker is adding `Check` next to `Doctor`.
- Docs: `docs/cli.md`, the `yaks` skill command table, `README.md` if it fits.
- `tests/hearth_import.rs` uses a small fixture repo built in the test: two pages, one source with an image linked as `../../raw/sources/...`, one schema, one session.

**Out of scope.** `links`, `pages`, `sources` and `schemas` internals (use their pub APIs), and the real `joel` repo, which is READ-ONLY for you.

**Evidence.**

- The test.
- A `--dry-run`, then a real import, of a SCRATCH clone of `~/src/fs/joel` (`git clone`; set `GIT_LFS_SKIP_SMUDGE=1` if LFS objects are missing) into a scratch farm. Paste the report and `yaks doctor`'s summary into a note.
- `yaks page list` count matches 31 and `yaks source list` count matches 37.
