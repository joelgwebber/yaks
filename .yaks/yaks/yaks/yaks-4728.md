Implements `yaks-a3fc` on the pieces that now exist: checkpoint notes (`--meta kind=checkpoint --meta branch=<b> --meta commit=<sha>`, `71ca61e`), landed notes from `yaks land` (`7e4a014`), `yaks commits` reading recorded shas, and sheds built from notes (`7393e45`).

## Scope

1. **`yaks commits <id> --fetch`.** For each distinct `branch` in the yak's notes that has a `remote` (default `origin`), run `git fetch <remote> <branch>` in the code repo, then list `git log --oneline <base>..<remote>/<branch>`. `base` is the note's `base` key, else the code repo's default branch (`origin/HEAD`, else `main`). Mark the recorded checkpoint commit in the list, and say when it isn't on the fetched branch (rewritten or not pushed). Without `--fetch`, use the remote-tracking ref already there, and say it may be stale. Also in `--json`.
2. **Sheds rows show where an actor's code is.** If the actor's latest `checkpoint` note (on any yak) names a branch, show `branch <b> @ <short sha> (<ago>)` on its row, in text, JSON and the TUI Sheds tab detail. No fetching here.
3. **Docs and help:** `docs/cli.md` (`commits`, `sheds`), `docs/tui.md` if the tab changes, `--help`. Not `.agents/skills/`.
