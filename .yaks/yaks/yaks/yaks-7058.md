Measured on a scratch copy of this farm migrated to schema 7, 2026-11-02, debug build. One `yaks update --note` makes 49 git calls with per-change commits on and 22 with them off (`YAKS_NO_AUTOCOMMIT`), taking about 0.7 s against about 0.26 s wall clock on this Mac. Most of the gap is repeated discovery: 6× `config --get yaks.branch`, 6× `rev-parse --is-bare-repository`/`--git-common-dir`, 5× `rev-parse --show-toplevel`, 2× `status --porcelain`. Cache discovery for the process, and build the snapshot and commit from one `status` call. Agents won't notice; a scripted bulk run (200 writes took 2m19s) and the TUI would.

Landed on local `main` as dd61f317 (not pushed).

- `store::farm_git`: the worktree's top level, git dir and configured branch are found once per process (one `rev-parse` plus the config read). The checked-out branch is read from the git dir's `HEAD` file each time, so a farm moved to another branch stops being a farm at once; a detached or reftable `HEAD` falls back to asking git.
- `changes::read` skips `ls-files` for a farm branch; `pending_operation` looks for `MERGE_HEAD`/`CHERRY_PICK_HEAD` as files in the git dir instead of two `rev-parse` calls.
- The commit identity (`git var`) and a checkout's common dir are asked once per process; `repo_config` is one call when the checkout is its own host (the host probe ran `--is-bare-repository` and a second `--git-common-dir` for nothing).

Spawns per `yaks update --note` from a checkout (discovery included): 30 before, 22 after; against `YAKS_DIR`, 33 before and 19 after. Test: `a_write_spawns_few_git_processes` in `tests/autocommit.rs` puts a `git` shim on `PATH` and asserts a bound (24 for a write, 12 for a command that writes nothing).

The TUI save, `:wq` in a comment on a clone of this farm (880 yaks), real pty, time to first output: 700-760 ms before, 345-390 ms after. The rest is the chip refresh (yaks-bcd4) and the second reload (yaks-1ebf).

Left alone because they are intrinsic to building the commit without touching the index: `status` runs twice (before the write and after, to find what the command changed), plus `show HEAD:path` for the commit message, `hash-object`, `read-tree`, `update-index`, `write-tree`, `commit-tree`, `update-ref`, `reset`. Gate: `cargo test` green; clippy count unchanged at 94 warnings.
