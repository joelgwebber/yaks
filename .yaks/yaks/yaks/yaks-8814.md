Seen 2026-10-12 on the real machine: land-1's shed (worker clone for yaks-ed5e) reads `farm: 1 moved, 17 new notes, 1 needs, 1 edited` instead of `landed`, although everything it did is in main. The one thing keeping it outstanding is its copy of yaks-ed5e still carrying `needs: human` (its blocked ask), which main later resolved (answered, picked up, needs cleared, then shorn). `outstanding_ids` treats any `needs:` the shed has and the reference lacks as outstanding, even when the reference has moved past it.

Refine: a shed's `needs:` is superseded (not outstanding) when the reference has no `needs:` on that yak AND the reference's notes include the shed's ask entry plus a later answer/pickup (or the reference yak is shorn). Same direction-aware spirit as the status_rank fix in yaks-ed5e. Evidence: a fixture with exactly this case reads `landed`; a shed whose ask the reference never saw stays outstanding.

Decision: the shed's ask is matched by the whole NoteEntry (timestamp + actor + text) via the shed's LATEST ask entry (`rfind(is_ask_text)`), found in the reference's notes at some position with at least one entry after it. Rejected: timestamp-only (two actors can write in the same second; a looser match could claim an ask the reference never saw); matching ANY ask in the shed (an old, already-answered ask must not resolve a newer one).

Decision: "a later note entry" is ANY entry after the ask in the reference (answer, pickup, or `moved:`), not specifically an answer/pickup text. Claim note says "followed by a later note entry"; the reference having no `needs:` plus the ask followed by anything means the needs was cleared after the ask. Rejected: requiring answer/pickup text (brittle against hand-written replies).

Decision: shorn reference with no `needs:` supersedes without checking notes (per the yak). Dead reference does not (not in the yak).

Decision: reference having `needs:` returns false from needs_superseded; case (d) in practice is not outstanding anyway because yak_changes does not report an identical `needs:` as new; the test pins that.

Decision: docs left unchanged: the existing wording ("its state there matches the reference exactly, or the reference is further along ... the reference already has everything the shed has for it") already describes this; a resolved `needs:` is the reference being further along. Grep: `grep -rn landed docs/cli.md .agents/skills/yaks/SKILL.md README.md src/main.rs`; none define landed more narrowly than that.
