## Gaps and speedbumps (for Joel)

- **Video transcript: not fetched.** YouTube answered 429 on the caption endpoint with every `yt-dlp` client I tried. The metadata worked. Next options: wait and retry, or `--cookies-from-browser` (uses Joel's browser login, so his call).
- **`x.com` returns an empty JavaScript shell** with HTTP 200, so a plain fetch looks like success. `api.fxtwitter.com/<user>/status/<id>` returns the tweet, the article blocks and image URLs as JSON. The skill says nothing about this.
- **No HTML-to-markdown tool on this machine.** I wrote a throwaway `bs4` script, which kept page chrome and repeated the T3 testimonial carousel until I de-duplicated it. The skill says "convert it with your own tools" but gives no recipe.
- **Images carry no text.** The manifesto screenshots needed me to read and transcribe them to be searchable. The transcription is a model's work and is labelled as such in each source.
- **`yaks` needs a git checkout as its working directory**, and the scratch directory where I download isn't one, so every command needs `-C <checkout>` with absolute paths. The error names the problem; the skill doesn't mention `-C` for this.
- **The skill and the binaries disagree.** The `yaks` skill in this checkout (0.0.31) says `yaks page ...`; the binary on `PATH` (0.0.32, `~/.cargo/bin`) calls it `yaks dok`, and the farm is schema 8. Three `yaks` binaries are installed (0.0.22 homebrew, 0.0.30 pnpm, 0.0.32 cargo). `PATH` order made the right one win, but only by luck. A `release` build of this checkout (0.0.31) refuses the farm.
- **A source's title is editable but there is no command for it.** I put a surname I had guessed into the YASS source's title, caught it, and fixed it by hand-editing `source.md`. Sources read as write-once, but there is no `yaks source set`, and `yaks commit` is needed to commit the hand edit.
- **Directory sources are heavy.** YASS is 2 MiB of files plus an 842 KiB `extracted.md` that concatenates them all. The farm's sources are now 2.3 MiB (LFS is on).
- **`yaks source list` does not show `--part-of` relationships**; I had to read `source.md` to confirm them. `yaks check` does know about parts.
- **`yaks check` is red until something cites each source**, by design. This note is the citation. `yaks doctor` still reports two dangling `depends_on` in older yaks (`yaks-5e8d`, `yaks-d262`), not from this work.
