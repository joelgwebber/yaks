It looks like we currently only render inline images in yaks/docs, if they're in their own block/paragraph. So a line like this doesn't render anything but the link:

`Here's an image: ![some image](some-image.png)`

At the very least we should render these on their own line if they're at the end of the block. But also fine to just render them regardless, splitting up the text block. I don't see any obvious reason to get wacky with text wrapping and other complex layout strategies.

Done in the working tree (not committed: awaiting a go-ahead to land).

## What changed

- An image in a top-level paragraph is now drawn under that paragraph whether or not it is the whole paragraph (`Here's an image: ![some image](...)`). The text is not split; the `🖼 alt` link row stays followable.
- Several images in one paragraph are drawn one after another, in order.
- Unchanged: an image in a list, quote, table or footnote stays the link row; remote, svg, missing or undecodable images stay the link row; `inline_images: false` still turns it all off.
- The rule is `MdImage::top_level` (was `alone`), set for every image of a top-level paragraph in [fn mark_top_level_images](code:src/tui/mdrender.rs#L606-L618); [fn md_rows](code:src/tui/detail.rs#L597-L641) now queues all of a paragraph's slots instead of the first.

## Evidence

- New test `an_image_among_text_is_drawn_under_its_paragraph`: three placements (end, middle, start of the text) each reserve 6 rows right after the paragraph and draw 6 pixel rows; two images in one paragraph reserve 12.
- Updated: `an_image_in_a_top_level_paragraph_is_flagged`, `image_size_token_is_hidden_and_carried_on_the_row` (their old expectations were the removed rule).
- `cargo test`: all pass (948 unit tests).
- Headless frame of the yak's own example: `Here's an image: 🖼 some image`, six reserved rows, then `After that paragraph.` The picture itself does not show in a text frame.
- Docs and help: `docs/tui.md` (Inline images), `README.md` (`inline_images`), the `?` overlay row in `src/tui/keymap.rs`, and the `inline_images` doc comments.

## Not done
