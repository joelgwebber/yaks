Joel, 2026-11-10: "let's file another yak to adjust our skill guidance, if needed, to capture that farming-out process, and relative model cost; though it may be that I'm restating this unnecessarily all the time."

He is restating it: `AGENTS.md` "Delegating to cheaper models" says it for this repo, but the bundled `yaks-coordinating` skill says only "Pass `model` only when the human asked for one", so every other farm (and this one, whenever a coordinator reads the skill before `AGENTS.md`) defaults to delegating on the coordinator's own model, or not at all.

## Proposal

Move the general part of `AGENTS.md`'s section into `yaks-coordinating` (a short "Choosing a model" under the brief or the Delta section), keeping the repo-specific numbers in `AGENTS.md`:

- **Default to a cheaper model for a delegable yak** (one outcome, a file/function scope, a test that can fail first); keep design, skill and prose rewrites, shared prep commits and every landing on the coordinator's model. Name tiers, not model ids (ids age): "the provider's mid tier" for workers, the coordinator's tier for review.
- **The cost is in review, not the brief:** budget the coordinator's re-run of each change (yaks-a3d2: two bugs the workers' tests missed).
- **A design-heavy yak on a cheap model** gets a scout pass from the coordinator first, or goes to the default model (herd-stars ran the keys rethink on the default model).
- **Say so in the landing note:** model per worker, so a later reflection can compare outcomes by tier.
- Relax "Pass `model` only when the human asked for one": a farm's `AGENTS.md` (or the person) sets the policy; the skill's default is the cheaper tier for delegable yaks.

Joel's harness setting "Only when asked" for subagents still wins where it applies; the skill should say a standing instruction in `AGENTS.md` counts as asking.

## Evidence

The skill diff; a cold read by a cheap scout of `yaks-coordinating` alone answering "which model do you give a worker for a one-function bug fix, and for a key-binding redesign?".
