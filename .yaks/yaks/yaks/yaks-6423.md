▸ 2026-10-31T19:56:30Z [yakherd]

Released v0.0.27 (yakherd, at Joel's request: "land all our changes, cut a release").

- **Landing.** The `yaks-039b` family, rebased a second time onto the human's `main` (`2d8fbf9`, `yaks-48e9`), went in cleanly. `main` was pushed to the human's checkout and to `origin` (`2d8fbf9..aaeaf65`).
- **v0.0.25** (tag `36fbdec`): the release run failed in `test`. The new `tests/commits.rs` ran `yaks commit` with no git identity, and CI has none (the same class as `yaks-1af5`). Nothing was published. Fixed in `f5fd1c1`, checked with `GIT_CONFIG_GLOBAL` set to `user.useConfigOnly`: that reproduces CI's `Author identity unknown` without the fix and passes with it.
- **v0.0.26** (tag `72f5b55`): tests passed, but both macOS builds failed. GitHub's `macos-14` images were in a scheduled brownout (they retire on 2026-11-02). Nothing was published. Moved both builds to `macos-15` (`e81bcd2`); a manual dry-run dispatch passed on all five platforms (run `41235556614`).
- **v0.0.27** (tag `aaeaf65`): run https://github.com/joelgwebber/yaks/actions/runs/41236048441 succeeded (tests, five builds, publish). npm `latest` is 0.0.27. A fresh `npm i @j15r/yaks@0.0.27` runs `yaks 0.0.27`, has `commits --fetch` and no longer has `discover`.
- **Local.** `cargo install --path .` gives `yaks 0.0.27`.
- **Leftover tags.** `v0.0.25` and `v0.0.26` remain as tags with no npm release. Delete them only if Joel wants to.

In this release: sheds built from note attribution, with `discover` and the activity log removed (`yaks-da23`, `yaks-d3ad`); note metadata, `update --meta`, `doctor` needs-drift and fence-aware notes (`yaks-6a11`, `yaks-b8cd`, `yaks-4cd7`); `yaks commits` fixed, landed shas recorded, `commits --fetch` and checkpoint branches on sheds (`yaks-7a11`, `yaks-735a`, `yaks-4728`); the `prs:` field (`yaks-d695`); skills for visibility across machines and for design questions as asks (`yaks-0071`, `yaks-4c2a`).
