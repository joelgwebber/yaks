Today `store::append_note` writes a comment as:

```text
<previous text>

---
▸ 2026-10-17T03:05:33Z [Joel Webber]

Any thing else
you can think of?
```

Under CommonMark (what GitHub, Delta and every `.md` viewer do, and now what our own renderer will do, see yaks-e9de), the `▸` line is a soft break away from the comment text, so it renders as one paragraph: `▸ 2026-10-17T03:05:33Z [Joel Webber] Any thing else you can think of?`. Checked with pulldown-cmark 0.13 on 2026-10-17. Also, a `---` directly under a text line (no blank line, possible in hand edits) is a setext H2, not a rule.

## Options

1. **Blank line after the header** (recommended): `---` / `▸ <ts> [actor]` / blank / text. The header becomes its own paragraph everywhere, stays greppable, and `content::parse` accepts both shapes, so old bodies keep working with no migration needed (an optional fixup can normalize them).
2. **Header as a heading**: `#### ▸ <ts> · actor`. It looks strong on GitHub, but it competes with headings inside comments and clutters outlines.
3. **HTML comment markers** (`<!-- yaks:note ts actor -->`): invisible in external renderers, so attribution disappears there. Rejected.

Whichever is chosen: `content::parse` / `assemble` (src/tui/content.rs), `store::append_note` / `split_note_head`, every other parser of the `▸` marker (`grep -rn 25b8 src`, `yaks log`, sheds note diffing), and the round-trip tests all move together, plus the skills' and docs' description of the format.
