Audit done (read-only, at main e4d0ff5a). The full inventory is in [audit.md](yaks-9714/audit.md), with path:line for every site.

**Summary, highest priority first**

1. **`store::farm_git` (`src/store.rs:522-541`) is the linchpin.** It treats `root.parent()` as the worktree top. If the farm root became the branch root it would return `None`, and the farm would silently stop counting as a farm branch: no per-change commits, and sync, preflight, weight, brief, `code_base` and `migration_refusal` all switch off. Fix it to accept `top == root` and give `FarmGit` a `prefix` (`""` or `".yaks/"`). That prefix becomes the one source of truth for "farm-relative to repo-relative".
2. **Silent misclassification:** `preflight::yak_id_of` (`src/preflight.rs:169-177`) needs a `.yaks` component. Without one, commit and status messages lose per-yak verbs. Also affected: `weight::kind_of` (`:90`), `sync.rs:251-255` (dirty test, which becomes a hard rebase failure) and the land guard `src/land.rs:606-622`, which would never fire.
3. **Attribute rules:** the merge driver's `ATTR_LINE` (`src/mergedriver.rs:37`) and the LFS globs (`src/weight.rs:324-333`) are `.yaks/**`. The migration must rewrite the existing `.gitattributes`, or LFS stops applying.
4. **Discovery and init:** `farm_branch_worktree` (`:377-391`), `shared_farm_worktree` (`:335-347`), `init.rs:291`, `:336`, `:380`, `store::init` (`:1487`, `root.exists()`), and `migration_refusal` (`:2679`, `{upstream}:.yaks/schema`).
5. **Old binary on a new branch fails hard with the wrong advice** ("restore .yaks/"). Mitigation: leave a stub `.yaks/schema` containing `9`, so old binaries hit the existing "newer schema, upgrade" refusal.
6. **Shared branch:** I reproduced a rebase in a scratch repo (git 2.56). Edits to renamed files carry over. A new yak file in a renamed dir gives a `UA` conflict. A new file in a dir that did not exist at the base stays stranded under `.yaks/`, even with `merge.directoryRenames=true`. So everyone must push before the migration, and/or migrate must sweep stray `.yaks/**` paths into place. `--follow` history survives (the schema-6 move was R100, and `git log --follow` crosses it).
7. **Smaller breakage:** `@sha` farm pins to pre-move commits break (`links::read_at` needs a `.yaks/` fallback beside `pre_doks_path`). The TUI's views, working set and drafts are keyed by `slug(root)`, so users lose them.

**yaks-bede, traced.** `/doks/sessions/...` parses to `Link::Farm{doks/sessions/...}`. `read_farm_doc` (`src/tui/follow.rs:95-98`) then fails, because sessions live at `sessions/`, a sibling of `doks/`. `/sources/<id>` fails anywhere: it is a directory, and `read_farm_doc` / `read_at` need a file. Only `/sources/<id>/source.md` works. `links::exists` skips extension-less paths, so doctor never reports the source case. The fix is one alias rule in a resolver, not in each caller.

**Proposed seam.** Keep `links.rs` as the pure grammar. Add `locate.rs`: a `Space` (farm root, `FarmGit{top,prefix}`, code checkout) with `resolve(Link) -> Place`, plus `local_path`, `content` (for the yaks-c3d0 viewer and peek) and `web_url`. Add `hosting.rs`: `Forge::detect` built on `store::normalize_remote_url`, plus `blob_url`. The remote rule moves from `sync::remote_of` to `gitrepo.rs`. In the TUI, `Target::{Farm,Source,Artifact}` collapse into one `follow(Place)` instead of today's three dispatch matches (`detail_nav.rs:387`, `handlers.rs:1455`, `:1615`). New verbs for copy-path and open-on-web would apply to any row or viewer.

**Size and split.** W1 discovery/`farm_git` (M, lands first). Then W2 git-top users (S), W3 classifiers and land guard (M), W9 cache slug (S) and W5 resolver (M) can run in parallel. W4 migration, attributes and LFS (L) owns `migrate.rs`, `mergedriver.rs` and `weight.rs`. W6 TUI (L, after W5) owns `handlers.rs` and `keymap.rs`. W8 docs, skills and clap help (M, last) owns `main.rs` doc comments.

**Test surface:** about 220 `.yaks` lines in unit tests and about 45 in `tests/`, plus the `tests/fixtures/farm/.yaks` fixture. 0 insta snapshots contain `.yaks`.

Decision: I reasoned the GitHub rendering table in audit.md §6 from GitHub's documented relative-link rules; I did not test it (that is yaks-7d13). Its main finding is that bare yak-id links and `code:` links stay dead on GitHub even after (A), and that a document-relative rewrite would reverse yaks-ccb1's "no `../`" rule.
