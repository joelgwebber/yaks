Done on branch `scheduling`.

- **Form.** `CreateForm` gains `due`, `every` (single-line rows) and `wakes` (a `none | agent | human` chip row) after `source`, so `HEADER_ROWS` is 8. They set and clear the same fields as the CLI (`due` through `recur::resolve_due`, so `+2d`/`+1w` work; a blank row or `none` clears). An edit form writes only the fields that changed. A `due` or `every` that does not read keeps the form open and says why (`due: "tomorrow" is not a date, a datetime or +2d / +1w`), so nothing typed is lost. Both forms treat the schedule rows as part of "dirty". `E` on a `Due:`/`Every:`/`Wakes:` detail line jumps to that row; the detail pane shows `Wakes:`.
- **Snooze.** `Z` (a `yak.snooze` binding in `keymap.rs`, list and detail) opens a one-line prompt for the new due date; Enter alone is `+1d`; it calls `Farm::snooze`, so the note and refusals match `yaks snooze`. With rows marked it snoozes them all and counts finished ones as skipped. A date that does not read puts the prompt back holding what was typed. `Z` is the lowest free capital: every change to an existing yak sits on Shift (the keys design dok), and the `?` popup and bottom hints are generated from the table.
- **Evidence.** Eight new tests in `mod live` (create sets all three; edit shows, leaves untouched and clears; bad due and bad every hold the form; dirty; `Z` on one yak with its note; `Z` default and bad input; `Z` over marked rows). Four form snapshots, the `?` popup and the help overlay were updated: I read every old-versus-new diff first (the form ones add exactly the three rows; the popup adds `yak.snooze`; the overlay is a fixed-height window that shifts one row). Driving the real binary with `yaks tui --headless` and looking at the frames showed the edit form on a recurring yak, the snooze prompt, the notification after Enter, and a refused `tomorrow`; the frames are attached (`yaks-2986-frames.md`). Looking found a real bug: the refusal notice was cut off at 78 columns, so the TUI now uses a short message. Full `cargo test` green (976 + 31 suites).
- **Docs.** `docs/tui.md` (edit-form paragraph, a `Z` row in the yak keys); the cli.md section already covers the fields.

Decision: `wakes` is a three-chip row, not a text field, because there are only two valid values and a chip cannot be mistyped. Decision: no separate `regrow` key: `S` already moves state.
