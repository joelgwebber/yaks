With sheds built from notes, visibility depends entirely on agents writing and syncing attributed notes. Make that the workflow, in `yaks`, `yaks-working`, `yaks-coordinating` and the `yaks brief` text.

- **Sync on every machine you aren't sitting at.** On a cloud runner, VM or remote box: `yaks sync` after every batch of yak writes. Nothing reaches other machines until it syncs, and a runner reset deletes the farm worktree (the memcraft runner was wiped twice in one day). Today the skill says "session start, after landing, before switching machines", which a long-running remote agent never hits.
- **Heartbeat notes.** Note at each milestone and at least every ~30 minutes of work, so "last write" means alive and `stale` means dead.
- **Name yourself.** Any agent thread sets `YAKS_ACTOR` to a short stable name at the start, not only briefed workers. Evidence: the memcraft farm has one thread split as `delta:ksQQIbEy…` (before Delta set the title) and `delta:Start investigation for yak mem-0908`.
- **Release claims.** Stopping without finishing: `regrow`, or a handoff note naming who takes it. Consider a `yaks doctor` check for long-stale claims.
- **Claim before code**, with the reason spelled out: with no git discovery, a claim is the only way unclaimed work is visible.
- Possibly, if the rules keep being missed: a farm setting that syncs after each write (for runners). Decide with evidence; not part of the first pass.

Cold-read the changed skills with a cheap scout afterwards (AGENTS.md).
