From yaks-2b40, point 6 (accepted by Joel 2026-11-10). A dok's `description:` is its index line: one sentence saying when to read it, so `yaks dok list` reads as an index. `yaks check` gains a finding for a dok with no `description:` (or an empty one).

- A new `check::Kind` (code `no-description`), its heading, the finding per dok path; `--json` like the others.
- Session notes are not doks for this purpose (they live under `sessions/`); schema files neither.
- `yaks dok list` shows the description when there is one (check what it prints today first; if it already shows it, leave it).
- Docs: `docs/cli.md` (`check`), clap help for `check` if it enumerates the kinds, the `yaks-upkeep` Housekeeping section is the coordinator's.

Decision: `Dok::description()` in `src/doks.rs` is the one rule (trimmed scalar, `None` when absent, empty, whitespace or a list). `check`, `dok list` and `--json` all use it. Rejected: reading `str_field("description")` at each site.

Decision: a dok with no frontmatter at all is not also flagged `no-description`: `doctor` already reports it as `dok-problem`, so one finding per problem. Rejected: flagging it twice.

Decision: `dok list` text prints the description on a second line, aligned under the title; a dok without one prints one line. Rejected: a trailing column (long lines wrap badly and the title column is ragged).

Decision: `description` (null when none) added to `json::dok_value`, so `dok list --json`, `dok query --json` and `dok show --json` all carry it; additive, `fields.description` is unchanged.

Decision: session notes and schemas are skipped because the check scans `doks::load_all`, which only walks `doks/` and `<herd>/doks/`. A test writes a description-less `sessions/` file to prove it.

Summary: new `check::Kind::NoDescription` (`no-description`) with a heading and one finding per dok path; `Dok::description()`; `dok list` shows the description under the title and `--json` includes it. Docs: `docs/cli.md` (check, dok list, dok show), clap help for `check` and `dok list`, one line in the `yaks` skill Doks section. Tests: unit test in `src/check.rs`, `tests/check.rs` (existing fixtures gained `description:`; new no-description cases incl. empty value and a session note), `tests/doks.rs` (list text and JSON).
