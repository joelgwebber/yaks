Findings (yaks-df61 O4/O15). (1) actor falls back to git user.name silently, so an agent that forgets --as writes notes that look human-authored (seen on yaks-7fa0). (2) shave/shorn/regrow/slaughter record no actor at all; --as exists only on verify/attach/update/ask/answer; git author is the human in Delta and often in git-worktree flows. (3) Delta terminals are fresh shells per call, so the skills' 'pin YAKS_ACTOR once per worker env' does not work; and agents have DELTA_THREAD_TITLE / DELTA_CURRENT_THREAD_ID but no YAKS_*. Options: (a) resolve from a harness identity when no actor is set (Delta env first; keep it a small pluggable list); (b) record the actor on transitions, folding into yaks-8265 (transition log), without changing the file layout lightly; (c) make the human-name fallback visible (marker or a doctor check). Evidence when done: a test per resolution path plus a real two-actor run whose notes and moves are attributable from the files alone. Also verify the git-worktree flows: the same gaps (2) and the silent fallback apply there; yaks-eb66 shipped only the note half.
