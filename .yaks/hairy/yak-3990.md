Allow filtering by:
- Next / tangled (dependency filters)
- Search (keyword filters)
- State (hairy, et al), Type, Priority, Labels

Design considerations: We already have a stateful UI for search results in the list view, but it's
purely ephemeral (as soon as you esc or navigate, it's lost). We might consider having a
persistent filtered list view that handles all filtered states, and is automatically selected when
searching a list.

One approach: Just put it to the left of "Hairy" so that you can always get back to it easily.

If we take this approach, we'll need to think carefully through the capabilities (e.g., mixed
filters) and interaction modes (how does one manage multiple filters flexibly, without creating
confusion).
