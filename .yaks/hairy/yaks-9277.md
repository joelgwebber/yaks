Decided by Joel (2026-10-06/07, in the notes of yaks-ee0a), not built except `landed` (yaks-ed5e): a shed has one state from a small vocabulary: active, idle, landed, stale, orphan. "Its claim disagrees with the primary" (its own copy of a yak is `shaving` while ours is `shorn`) is a SIDE NOTE on the row, not a state. Liveness starts as the simplest signal: no farm activity for N hours while its own yak is still `shaving`; revisit only if it misleads. The tools never remove or clean up a shed: they name what is safe and may print the command.

Goal: define each state precisely (inputs: commits ahead/behind, dirty count, farm activity time, whether its changes are all in this checkout, whether its git dir or checkout is gone), show it in `yaks sheds` (text and JSON) and `yaks changes`, and record the definitions as Decisions. Design first with Joel; the TUI badges (yaks-7204) consume this.

Real-machine cases to define against (2026-10-10, ~/src/j15r): two clones with identical HEAD and identical uncommitted farm files, whose yaks are all further along in the primary (shorn there, `shaving` in the shed): that is `stale`, not outstanding work (see the note on yaks-ed5e). A pinned clone whose git dir is gone is `orphan`-adjacent (a finished thread).

▸ 2026-10-11T20:15:37Z [delta-lead]
Design question for Joel before any code (per this yak's own instruction). `yaks-ed5e` is in progress and resolves `landed` as: every yak the shed changed (relative to its own fork point) is already captured in the reference farm (the primary's live farm, else `origin/main`) — this covers both "exactly landed" and "superseded by the reference" in one check.

**The tension.** The original decision (2026-10-07) lists `active, idle, landed, stale, orphan` as ONE mutually exclusive vocabulary. But the real-machine case written into THIS yak ("two clones with identical HEAD and identical uncommitted farm files, whose yaks are all further along in the primary... that is `stale`, not outstanding work") describes exactly the SUPERSEDED case that `yaks-ed5e` now calls `landed`. So either the case note used "stale" loosely before the vocabulary was pinned down, or `stale` and `landed` are meant to overlap on purpose. I don't think they should mean the same thing, but there are a few ways to split them. Options:

**A. Liveness and landedness are orthogonal — two fields, not one enum.** `landed: bool/count` (from `yaks-ed5e`) answers "is anything outstanding". A separate liveness signal (`active`/`idle`/`stale`) answers "is anyone still touching it" and applies regardless of landed-ness. A shed can be landed-and-idle (the common case: it's done, nobody's touched it since), landed-and-stale would be unusual (its own idea of "shaving" disagrees with the reference's "shorn", but there's genuinely nothing outstanding — your real-machine case fits this), or outstanding-and-active (real work in flight) or outstanding-and-stale (abandoned mid-work — the case the original liveness heuristic was written for). `orphan` stays a third, separate bit (pin resolves to a gone git dir — can't even read it). This keeps `landed` exactly as `yaks-ed5e` ships it and adds liveness beside it, not instead of it.

**B. One priority-ordered enum, `landed` wins over the liveness states.** `orphan` > `landed` > `active` > `stale` > `idle`. A shed with real outstanding work and recent activity is `active`; with outstanding work and no activity for N hours it's `stale`; with nothing outstanding at all it's `landed` regardless of activity (so your real-machine case reads `landed`, not `stale`, despite the literal wording in the earlier note). This keeps one word per shed (simpler to render as a single badge) but means the earlier case note's wording was imprecise and should be corrected, not taken as the definition.

**C. Keep `stale` as liveness-only (matches the 2026-10-06/07 decision text exactly: "no farm activity for N hours while its own yak is still shaving"), and fix the case note's wording instead of the vocabulary.** The two "stale" j15r clones would be `landed` (ed5e) and ALSO flagged stale by liveness if nobody's touched them in N hours — same outcome as A, phrased as "the note used the wrong word, not that two concepts collapse."

My lean: A. It keeps `yaks-ed5e`'s landed exactly as specified (nothing to redo there), and a one-enum design (B) would have to special-case "landed but also been idle forever" vs "landed and just finished a minute ago" if that distinction ever matters — A keeps that open for free. C is really the same resolution as A with a different enum shape; I'd rather not force one combined enum if the two questions ("anything outstanding" and "is it alive") already have clean independent answers.

Also open: the liveness THRESHOLD (what counts as "no activity for N hours" — a fixed default, configurable, or derived from something else), and whether `orphan` is detected here (git dir gone) or already fully covered by `yaks discover`'s existing "gone" reporting and this yak only needs to surface it on the `sheds` row.
