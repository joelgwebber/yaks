If you filter on a keyword or label, and a yak's *parent* doesn't match, then it won't display even if the child *does* match.
I think the right approach would be to use a similar bright/dark affordance to the one we do in other filtering operations (e.g., by shaving state).

---
▸ 2026-06-19T20:39:48Z
Fixed in yaktui/tree.py build_tree. Root cause was two-fold: (1) the keyword-search branch flattened to a context-less depth-0 list, and (2) the structured-filter branch only treated current-tab-status yaks as match candidates, so a matching child in a different status than the tab (e.g. a hairy child held in view by its shaving parent) was dropped. Rewrote build_tree around one model: the tab anchors a 'universe' (tab-status yaks + ancestors + descendants, any status = exactly the unfiltered tab view); an active content filter then lights up matches anywhere in that universe (bright) with non-matching ancestors pulled along as dim ghosts to root them, pruning the rest. Search now flows through the same path (no more flattening). Not a global cross-tab search: a match with no relative in the current tab stays hidden. 4 new tests; all 110 pass; existing ghost/filter/status-override tests preserved.
