Claim (coordinator). Owner: inbox-1.
Goal: `yaks inbox --sheds` adds, after the normal inbox, every OTHER shed's open asks: yaks whose `needs` is set in that shed's own farm. For each, the shed's name (`Shed::name()`), its path, the yak id, the title, `needs: human|agent`, and the question text (the newest note entry at or after the ask; reuse whatever `inbox` already uses to pick the ask or reply text, and do not reimplement note parsing: `store::parse_notes`). Asks that are identical in this checkout's farm (same id, same needs value and the same latest note) are NOT repeated, since you already see them above. A shed whose farm is Shared (private farm) or None shows nothing. The `--for human|agent` filter and the FilterFlags apply to the shed rows too. `--json`: keep the current inbox JSON shape when --sheds is absent; with --sheds, add a top-level key or wrapper and record the shape you chose as a Decision: note.
Data: reuse `sheds::discover(cwd, farm_root)` for the shed list (it is read-only). Load each shed's farm with `store::discover_with(shed.path, None)` + `store::load`, as `sheds::inspect` already does. NEVER write to another checkout.
Scope: src/main.rs (the `Inbox` variant: add `--sheds`; `render_inbox` or a new render function beside it), src/farm.rs (a new read-only fn beside `Farm::inbox`, or a function in src/sheds.rs: your choice, recorded as a Decision:). Docs: docs/cli.md (the inbox row), README.md, `.agents/skills/yaks/SKILL.md` (the inbox line), clap help.
Out of scope: answering across sheds (a later yak), `-C`.
Evidence: tests that FAIL before your change: a repo with a git worktree whose farm has an ask that the main farm lacks; `inbox --sheds` from the main checkout shows it with the shed's name and the question text, and plain `inbox` does not. An ask present identically in both is listed once. A shared-farm shed adds nothing. Judge: the coordinator, at landing.

Decision: the shed scan is `Farm::inbox_sheds` in src/farm.rs beside `Farm::inbox` (shares one `needs_rows` predicate with it), not a function in src/sheds.rs. Rejected: sheds.rs, because sheds.rs is about git/farm *deltas* and I was told not to touch discover/resolve/shed_paths; farm.rs already owns the inbox meaning.
Decision: the question text comes from two new `store.rs` fns on top of `parse_notes`: `ask_note` (newest note at/after the latest `asked: needs` note, skipping `moved:`/`picked up`, same rule as `is_replied`) and `ask_question` (that note minus the `asked:` marker line). Rejected: reimplementing note parsing in farm/main; showing the whole body. A hand-set `needs:` (no ask note) shows "(no question text)" / JSON `question: null`.
Decision: dedupe = same id AND same `needs` AND equal `ask_note` in this checkout's farm (loaded in full, any status). Rejected: id-only (would hide a shed's re-ask or reply), and comparing whole bodies (a shed's unrelated notes would defeat the dedupe).
Decision: only `ShedFarm::Own` sheds are scanned. Shared/None/Unreadable add nothing, per the claim. The shed farm is loaded with `store::discover_with(shed.path, None)` + `store::load` (read-only).
Decision: `--json` with `--sheds` is an object `{"inbox": [...same array as before...], "sheds": [{shed, path, id, title, status, needs, replied, question}]}`; without `--sheds` the flat array is unchanged. Rejected: appending shed rows into the flat array with a `shed` key (would silently change consumers that count the array, and mixes our yaks with theirs); a wrapper in both modes (breaks the existing shape).
Decision: text output = the normal inbox first (its "Inbox empty" line is now printed and then falls through when `--sheds` follows, instead of returning early), then one `Shed <name> (<path>):` header per shed, each ask as a normal `fmt_row` plus the question lines indented. With nothing: "No open asks in other sheds.". Rows are grouped by shed because sheds are iterated in `discover` order (sorted by path).
Decision: `--for` is applied to shed rows by `Audience::keeps` in main.rs after `inbox_sheds` (which takes the FilterSpec for the other filters), rather than inside Farm, because `--for` is a CLI-only concept (`Audience` lives in main.rs); the text/JSON of plain `inbox` is unchanged.
Decision: `shed` is `Shed::name()`: for a worktree shed that is the first note actor (`who`), else branch/dir name. Two sheds can share a name; `path` disambiguates.
Evidence: tests/inbox_sheds.rs (6 tests, real binary + real git worktree: listed with name+question and absent from plain inbox; identical ask listed once and a re-asked one is not hidden; --for + JSON shape; shed with no farm; shed whose `.yaks` is a symlink to ours; shed farm untouched (git status + mtimes)) plus 2 unit tests for ask_question in store.rs. With the src changes stashed (tests only) all 6 integration tests FAIL (no `--sheds` flag); with them they pass.
