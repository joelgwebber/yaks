▸ 2026-10-09T03:48:47Z [delta:ksQQI7UGw66zRMm9tnfRIaYEapLOAAa8q5IBxBCA]
Built `yaks discover [PATH] [--root DIR]` (src/discover.rs): a read-only, farm-free diagnostic showing what each source finds from an anchor and why each candidate was accepted or rejected. Sources are `git worktree list`, the Delta sibling scan (`yaks sheds` today), and the Delta roots (platform default plus `--root`). All of them use one matcher, `sheds::repo_match`.

Findings (evidence attached: discover-mac.txt from the real Mac; discover-fixture.txt from `scripts/discover-fixture.sh`, a synthetic repo with 2 git worktrees, a linked and a managed Delta clone, another repo, and an orphan mount):
1. The model holds. From a primary checkout, a git worktree, or a worktree subdirectory, the union of the three sources finds every other shed.
2. From a Delta clone, plain git worktrees of the primary are NOT found (the known gap). The fix is to also run `git worktree list` in the repo that `alternates` / `local` names.
3. From a MANAGED clone, nothing at all is found. Its alternates and `local` point at the managed bare repo, and the sibling scan looks for `*/local_<uuid>`, a name unique to that clone. Only the root scan plus an origin match finds its siblings, and nothing finds the user's checkout.
4. Decision: a mismatch in alternates no longer rejects a candidate; matching falls through to origin. A linked clone and a managed clone of one repo borrow different stores, so the old rule hid the managed clone from linked clones. Rejected alternative: keep the reject and accept only from the primary. That makes the verdict depend on the anchor. Origin URLs are normalized (trailing `.git` and `/` ignored), because Delta records `https://github.com/o/r` while `git clone` records `r.git`.
5. Mac reality: the Application Support root holds 2 real managed checkouts (other repos) and 2 orphaned mounts (a file tree with no `.git` and no sibling `.git` dir). These are rejected as `no .git`.
`yaks sheds` does not use the root scan yet; that is the next step.
