The additive half of yaks-73f4's design, built while round 2 runs: (1) `store::discover_with`: when the walk stops at a git top-level with no `.yaks` entry, resolve the farm branch (`git config yaks.branch`, default `yaks`) to its worktree via the host's `git worktree list` (`sheds::worktree_of_branch`); a branch that exists (local or origin/) with no worktree is an error naming `git worktree add <path> <branch>`; neither keeps today's error. (2) `store::farm_branch(root)`: the farm branch a root is a dedicated worktree of (its HEAD is the configured farm branch, or its config names `live_branch:`); `brief` Mode::Live and `source_base` key on it instead of the config line, so both keep working after the migration drops `live_branch:`. `sync_live`/`--land` stay until the migration commit. Evidence: discovery tests with a real orphan worktree (from the code checkout, a subdir, a plain worktree, a --shared clone; branch-without-worktree error; no branch: old error); brief and source tests on an orphan farm.
