Round 1 of yaks-6a34 left merge spaghetti on main: one `Merge worker commit` per landing (land.sh always `merge --no-ff`) and one `Merge remote-tracking branch 'local/farm'` per landing (farm never contains main's code commits, so every farm->main merge is a real merge). Joel: squash workers; keep the farm on main for this repo (option (a)).

1. land.sh: the main path becomes a squash. When the worker's base is an ancestor and merge-tree is clean, commit the computed tree as ONE commit on HEAD (`git commit-tree <tree> -p HEAD`, the worker's message and author, a `Squashed from worker commit <sha>` trailer), fast-forward to it, check the tree. Otherwise cherry-pick (already a single commit). No merge commits on either path.
2. The live farm lands linearly. `yaks commit --land` (live farm only): commit the farm as usual, then cherry-pick onto the invoking checkout's HEAD every live-branch commit whose patch HEAD does not have (`git cherry`). And `yaks commit` in a live farm first moves the live branch onto the code base branch (`main`) with a mixed reset (ref + index only; uncommitted yak edits untouched) whenever every farm commit is already on it by patch, so the farm stays a short line on top of main and never diverges.
3. The farm worktree uses a pattern sparse checkout (`sparse-checkout set --no-cone '/.yaks/'`): only `.yaks/` on disk, since the farm branch now carries main's whole tree.
4. Skills/docs: team skill "Live farm", the Delta landing section and `yaks commit` docs say `yaks commit --land` replaces `fetch local farm && merge local/farm`.

Evidence: land.sh selftest asserts one single-parent commit whose tree equals the computed merge; Rust tests for `--land` (cherry-picks only new farm commits, idempotent on a second run) and for the farm move (drift survives, farm == main afterwards); a real landing on this machine leaving a straight line on main.

Done (delta-farm). `land.sh` squashes by default: the computed merge tree becomes ONE commit on HEAD (`commit-tree -p HEAD`, the worker's message, author and date, a `Squashed-from: <sha>` trailer), fast-forwarded and checked against the computed tree; the cherry-pick path is unchanged. `yaks commit --land` (src/commit.rs `land`): commit the live farm, fetch the farm branch tip into the invoking checkout, cherry-pick `rev-list --right-only --cherry-pick --no-merges HEAD...<tip>` oldest first (aborts cleanly on a conflict). `commit::sync_live`, run by every non-dry `yaks commit`: mixed-reset the live branch onto `main` when main's `.yaks/` tree is IDENTICAL to the branch's.

Decision: the sync condition is tree equality of `.yaks/`, not "every farm commit is on main by patch". Rejected the patch test: it would also need the cherry-picked commits' patches to apply identically, while tree equality is exactly "resetting loses nothing committed" and is one `rev-parse` each. Rejected moving farm inside `--land` (after the picks main is not yet pushed; the next commit does it once main has them).

Decision: squash, not rebase, for workers (Joel). The farm is cherry-picked, not squashed, so each herding commit keeps its generated message.

Evidence: land.sh selftest (scenario 1 now asserts one single-parent commit on HEAD + the trailer, 21/21 ok); commit tests `land_cherry_picks_farm_commits_linearly_across_rounds_and_keeps_drift` (two rounds, zero merge commits, drift survives the reset, farm worktree never gains `src/`), `sync_live_never_moves_a_farm_commit_main_lacks`, `land_refuses_outside_a_live_farm_and_from_the_farm_worktree`. Full `cargo test --release` 857 passed. Docs/skills: docs/cli.md (commit row, live-farm rule), README, AGENTS.md, yaks skill, team skill "Live farm", Delta skill landing step, store errors now say `--no-cone '/.yaks/'`.
