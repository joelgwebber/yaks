Joel (2026-10-12): consider a second cross-shed write for steering a worker ("downward guidance"): a note written into a worker's copy of its yak, e.g. `yaks update <id>@<shed> --note "..."` and a TUI key on a shed's yak. Without it, guidance goes through the coordinator and has to be merged down to the worker, which is too much machinery for a simple problem. In a private farm every shed already shares one farm, so a note is visible everywhere at once; this is a team-farm problem.
Today only `answer <id>@<shed>` may write into another checkout (decision on yaks-ee0a, 2026-10-06). Design questions: does a guidance note set `needs: agent` (so the worker's inbox shows it) or is it a plain note the worker only sees if it re-reads; how does a running worker notice it at all (it does not poll its yak; in Delta the nudge is a message to the agent); and the loss hazard filed beside this (an uncommitted cross-shed write lost when the worker syncs).
